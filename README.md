# Telegram-бот для подачи и обработки заявок

Асинхронный бот на **aiogram 3** + **SQLAlchemy 2 (async)**. Пошаговая анкета, хранение ответов и медиа в БД,
админ-панель с inline-меню, статусы, комментарии, уведомления, статистика, роли администраторов.

## Установка

Нужен Python 3.10+ (рекомендуется 3.12).

```bash
cd application_bot
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # Windows: copy .env.example .env
```

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Узнайте свой Telegram ID (например, у [@userinfobot](https://t.me/userinfobot)).
3. Заполните `.env`:

| Переменная | Описание | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен бота **(обязательно)** | — |
| `MAIN_ADMIN_ID` | Telegram ID главного администратора **(обязательно)** | — |
| `DATABASE_URL` | строка подключения к БД | `sqlite+aiosqlite:///data/bot.db` |
| `TIMEZONE` | часовой пояс для дат и «за сегодня» (IANA-имя) | `UTC` |
| `PAGE_SIZE` | заявок на странице списка | `10` |
| `NOTIFY_ADMINS_ON_NEW` | уведомлять админов о новых заявках | `true` |
| `MAX_PENDING_PER_USER` | лимит заявок «на рассмотрении» у одного пользователя, `0` — без лимита | `0` |
| `LOG_LEVEL` | уровень логирования | `INFO` |

> Главный администратор должен хотя бы раз написать боту `/start`, иначе Telegram не даст боту писать ему первым.

## Запуск

```bash
python -m appbot
```

Логи — в консоль и в `logs/bot.log` (ротация 5 × 5 МБ).

**Docker:** `docker compose up -d --build` (данные в `./data`, логи в `./logs`).

**systemd** (пример `/etc/systemd/system/appbot.service`):

```ini
[Unit]
Description=Applications Telegram bot
After=network-online.target

[Service]
WorkingDirectory=/opt/application_bot
ExecStart=/opt/application_bot/.venv/bin/python -m appbot
Restart=always
User=bot

[Install]
WantedBy=multi-user.target
```

## Настройка вопросов анкеты

Откройте `appbot/questions.py` и правьте список `QUESTIONS`. Перезапустите бота — всё.
Количество вопросов не ограничено.

```python
Question(
    key="nick",            # уникальный ключ (латиница/цифры/_/-), не меняйте у работающего бота
    label="Ник",           # подпись в карточке заявки
    text="Ваш ник?",       # текст вопроса пользователю
    type=QType.TEXT,
    max_length=64,
)
```

Типы ответов (`type`):

| Тип | Что принимает |
|---|---|
| `QType.TEXT` | текст (опционально `max_length`, `pattern` + `pattern_error` для regex-проверки) |
| `QType.NUMBER` | целое число (опционально `min_value`, `max_value`) |
| `QType.PHOTO` / `VIDEO` / `DOCUMENT` | фото / видео / файл-документ |
| `QType.MEDIA` | любые медиа: фото, видео, документы, GIF, аудио, голосовые, «кружки» |
| `QType.ANY` | текст **или** любой один файл |

Дополнительные параметры:

- `required=False` — вопрос можно пропустить кнопкой «⏭ Пропустить».
- `multiple=True` (медиа-типы) — несколько файлов подряд, завершение кнопкой «✅ Готово»; границы `min_files`, `max_files`.
  Альбомы (несколько файлов одним сообщением) обрабатываются корректно.
- `APPLICATION_TITLE_KEY = "nick"` — ответ, который показывается как заголовок в списке заявок (`#125 — Nazar_Alfons`).
  `None` — показывать @username.
- `APPLY_INTRO` — вступительный текст перед первым вопросом.

Можно свободно **добавлять, удалять и переставлять** вопросы: уже поданные заявки хранят собственные снимки
подписей и текстов вопросов и не ломаются. Незавершённые черновики продолжатся с первого вопроса без ответа.

## Настройка базы данных

**SQLite (по умолчанию)** — ничего настраивать не нужно, файл создаётся в `data/bot.db`.
Включены WAL-режим и внешние ключи. Для бэкапа достаточно копировать `data/bot.db*` (или `sqlite3 data/bot.db ".backup copy.db"`).

**PostgreSQL** (рекомендуется при высокой нагрузке):

```bash
pip install asyncpg          # или раскомментируйте в requirements.txt
```
```
DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/applications
```
База должна существовать; таблицы создаются автоматически при первом запуске (`create_all` добавляет только отсутствующие таблицы).
Для изменения схемы существующих таблиц в будущем подключите [Alembic](https://alembic.sqlalchemy.org/) — модели уже на SQLAlchemy 2.0.

Таблицы: `users`, `admins`, `applications`, `answers`, `media` (в т.ч. Telegram `file_id`, тип, имя, MIME, подпись),
`status_history` (кто, когда, из какого статуса в какой и с каким комментарием).

## Роли и команды

| Команда | Кто |
|---|---|
| `/start`, `/apply`, `/cancel`, `/myapplications` | все |
| `/applications`, `/stats`, `/admins` | администраторы |
| `/addadmin ID`, `/removeadmin ID` | главный администратор |
| `/addadmin ID manager` | только главный администратор — выдаёт право управлять администраторами |

- **Главный администратор** (`MAIN_ADMIN_ID`) — все права, удалить его нельзя.
- **Обычный администратор** — работает с заявками, но не может выдавать/снимать права.
- **Администратор-управляющий** (`manager`) — право «разрешено отдельно»: может добавлять и удалять обычных админов,
  но не других управляющих и не главного.
- Любой не-админ при обращении к админ-функциям получает «⛔ недостаточно прав»; проверка идёт в БД перед каждым действием.

Работа администратора: `/applications` → список (по 10 на страницу, фильтры по статусу, ⬅️/➡️, 🔄) → нажатие на заявку открывает карточку
со всеми ответами и присылает все файлы (альбомами). Кнопки 🟢 Одобрить / 🔴 Отклонить (с необязательным комментарием, который уйдёт пользователю) /
🟡 Вернуть на рассмотрение, 📜 История статусов.

## Как это работает (важные детали)

- **Анкета хранится в БД**, а не в памяти: заявка создаётся как черновик (`draft`), каждый ответ сохраняется сразу.
  Текущий вопрос = первый без завершённого ответа, поэтому после перезапуска бота заполнение продолжается с того же места.
- **Защита от параллельных заявок:** один черновик на пользователя (частичный уникальный индекс в БД) + апдейты одного
  пользователя обрабатываются строго по очереди. Опционально — лимит `MAX_PENDING_PER_USER`.
- **Отмена:** `/cancel` или кнопка — черновик получает статус `cancelled` (данные остаются для аудита, админам не показываются).
- **Нумерация:** ID выдаётся при начале заполнения, поэтому отменённые черновики оставляют «дыры» в нумерации.
- **Длинные ответы:** если карточка не помещается в 4096 символов, ответы приходят отдельными сообщениями без потерь.
- **Уведомления:** пользователю — об отправке и смене статуса (с комментарием); админам — о новых заявках. Если пользователь
  заблокировал бота, админ увидит предупреждение.
- **Ошибки Telegram API:** flood-лимиты (повтор после паузы), блокировка бота, «message is not modified», устаревшие сообщения —
  обрабатываются; неожиданные ошибки пишутся в лог с трассировкой, пользователь получает вежливое сообщение.
- **Единственное состояние в памяти** — шаг «ввод комментария администратора» (FSM `MemoryStorage`). При перезапуске админ просто
  откроет заявку заново. Для нескольких процессов замените хранилище на `RedisStorage` в `main.py`.
- «За неделю» в `/stats` — последние 7 суток; «за сегодня» — с полуночи в `TIMEZONE`.

## Расширение

- Новый тип вопроса: добавьте значение в `QType` (`questions.py`), правило приёма в `_handle_answer` (`handlers/apply.py`) и подсказку в `texts.question_hint`.
- Новые админ-функции: добавляйте хендлеры в `handlers/admin.py` — роутер уже защищён `AdminOnlyMiddleware`.
- Webhook вместо polling: замените `dp.start_polling` в `main.py` на aiogram-вебхук-сервер.
